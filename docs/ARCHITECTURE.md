# Архитектура

Краткое описание хранения, извлечения и переиспользования SVG-элементов, а также общей структуры проекта. Полное ТЗ — [`SPEC.md`](./SPEC.md), ход работы по этапам — [`PROGRESS.md`](./PROGRESS.md).

## Принцип

SVG-библиотека обрабатывается один раз на этапе сборки. Рантайм только читает готовый манифест и рисует объекты — исходные файлы `assets-src/` нигде не переписываются вручную.

```
assets-src/            исходные SVG из Figma (неприкосновенные оригиналы)
       │
       ▼  npm run library (scripts/build-library.ts)
src/library/            СГЕНЕРИРОВАНО: manifest.json + нормализованные SVG
       │
       ▼  (ручной файл-исключение из этой же папки)
src/library/semantics.ts  словарь смыслов для core/matcher
       │
       ▼  читается рантаймом
src/stores/library.ts   доступ к манифесту и ленивая загрузка разметки
       │
       ▼
Vue-компоненты (<symbol>/<use> на холсте) и core/export (инлайн-копии при экспорте)
```

## Хранение

- `assets-src/` — экспорт из Figma: 10 объектов × 2 состояния (главный/фоновый) = 20 иллюстраций, каждая в двух размерах L/S = 40 объектов-ассетов, плюс 6 файлов фоновых подложек (3 схемы × 2 размера) и 3 файла палитр.
- `scripts/build-library.ts` (`npm run library`):
  1. Парсит каждый SVG XML-парсером (`@xmldom/xmldom`), не регулярками.
  2. Валидирует: запрещены `<image>`, встроенный растр, внешние ссылки; обязателен `viewBox`. Нарушение — явная ошибка сборки с именем файла.
  3. Не меняет геометрию. Удаляются только комментарии/пустые `defs`/метаданные.
  4. Классифицирует каждый `fill`/`stroke` по канонической роли (раздел 5 `SPEC.md`), заменяя его на `fill="var(--role-x, #fallback)"` + `data-role="x"`. Цвет вне канона — сборка падает, пока не решено явно.
  5. Префиксует все `id`/`clipPath`/`mask`/`url(#...)` уникальным префиксом `{id}-{size}-{state}-`.
  6. Считает `bbox` и пишет `src/library/manifest.json` (тип `LibraryManifest` в `src/shared/types.ts`).
- `src/library/semantics.ts` — единственный файл в этой папке, который не генерируется: ручной словарь смыслов для сценария 1 (раздел 6.6 `SPEC.md`). Защищён от случайной правки хуком `guard-protected-paths.cjs` так же, как остальная `src/library/`, но с точечным исключением именно для этого пути.

## Извлечение и переиспользование (рантайм превью)

- `src/stores/library.ts` лениво подгружает сырой SVG нужного `objectId`/`size`/`state` через `import.meta.glob('../library/**/*.svg', { query: '?raw' })` и кэширует результат как `Promise` (конкурентные запросы на один и тот же символ не дублируют загрузку).
- Все нужные ассеты вставляются в один скрытый `<svg>` как `<symbol id="...">`. Экземпляр на холсте — `<use href="#...">` внутри `<g transform="...">` (`src/features/canvas/CanvasItem.vue`, формула трансформа — единственный источник правды в `src/features/canvas/geometry.ts::itemTransform`).
- Один и тот же объект можно добавить на холст сколько угодно раз без копирования разметки — только новый экземпляр `<use>` с тем же `assetId`.
- Смена размера L/S или состояния main/bg — замена `assetId` экземпляра, трансформ (позиция/поворот/отражение) сохраняется.
- Цвет: элементы символов используют `fill="var(--role-…, #fallback)"`. Смена палитры — перезапись 8 CSS-переменных на корне холста (`core/recolor/recolor.ts`), DOM не перерисовывается.

## Экспорт (другой путь переиспользования)

`core/export/export.ts` строит самостоятельный SVG для скачивания:
- каждый объект — **инлайн-копия** оригинальной геометрии (`<g data-object="..." transform="...">`), не `<use>` — чтобы результат было удобно редактировать в Figma/Illustrator без доступа к `<symbol>`-дереву;
- роли цвета разрешаются в конкретный hex выбранной палитры (CSS-переменные в экспортный файл не попадают);
- `id` внутри каждого экземпляра переприсваиваются уникально (тот же паттерн, что `prefixIds` в `build-library.ts`, но на уровне одного экспортируемого документа);
- инвариант, проверенный golden-тестом (`tests/unit/export-golden.spec.ts`): набор геометрических атрибутов каждого объекта идентичен исходнику, меняются только цвет и внешний `transform`.

## Автоматизация

- `core/layout` — детерминированная раскладка по seed (`mulberry32`, 200 кандидатов, скоринг по покрытию/балансу/пересечениям/видимости главного объекта).
- `core/matcher` — подбор объектов по метафоре (TF-IDF-подобное взвешивание словаря `semantics.ts`, нечёткое сравнение опечаток) и по явному списку компонентов (нечёткое сопоставление с `nameRu`/`id`/синонимами). Работает полностью локально, без сети и внешних API.
- `src/features/scenarios/compose.ts` связывает результат подбора с раскладкой и заменяет сцену одним шагом истории (`sceneStore.replaceItems`).

## Свободный размер холста

Поверх трёх пресетов форматов (раздел 6.3 `SPEC.md`) можно задать произвольный размер холста: `Scene.customSize` (опционально, `src/shared/types.ts`), ограничен 400–2400 по стороне (`clampCanvasSide`, `src/shared/formats.ts`). `resolveFormat(scene)` — единая точка, которая возвращает либо пресет, либо пресет с подставленными `customSize`-размерами; и `core/layout`, и `core/export`, и холст используют только её, не читают `Scene.format`/ширину-высоту напрямую. Выбор одного из трёх пресетов (`CanvasSettings.vue`) сбрасывает `customSize`. Размер кадра управляется слайдерами/ручками на холсте панели «Холст».

### Общий масштаб объектов

Масштаб объектов больше не «всегда 1»: у сцены есть один общий коэффициент `Scene.objectScale` (`src/shared/types.ts`). По умолчанию он авто (поле не задано): `resolveObjectScale` (`src/core/layout/object-scale.ts`) берёт самый крупный bbox сцены и подбирает коэффициент так, чтобы он занимал не более `LAYOUT_AUTO_SCALE_MAX_AREA_RATIO` (~45%) площади кадра; результат ограничен диапазоном 0,3–1,0. Вручную коэффициент задаётся ползунком «Масштаб объектов» (кнопка «Авто» сбрасывает поле), изменение батчится в один шаг undo и сохраняется в autosave. Коэффициент применяется только к внешней группе экземпляра (`itemTransform(item, bbox, objectScale)`, как поворот): и холст (`CanvasItem`), и `core/export` используют одну и ту же функцию, `core/layout` считает bbox с тем же коэффициентом. Пропорции объектов между собой и их геометрия не меняются: внутри группы все атрибуты идентичны исходным (golden-тест).

## Токены UI vs роли палитры композиции

`src/styles/tokens.css` содержит `--color-ink: #1A1A1A` — это цвет **текста интерфейса** (раздел 7 ТЗ). Роль `ink` в палитрах композиций (`src/palettes/*.json`, например `#181817` в фиолетовой схеме) — это цвет контуров **объектов иллюстраций**. Это два независимых по смыслу значения: одно про UI сервиса, другое про цветовую схему композиций раздела 5. Их совпадение не требуется и не предполагалось.

## Зависимости (обоснование новых, помимо стандартного Vue/Vite/Pinia-стека)

| Пакет | Зачем |
|---|---|
| `@xmldom/xmldom` | XML-парсер для `build-library.ts` (без regex-парсинга SVG) |
| `zod` | Валидация схемы палитры с понятными ошибками |
| `@resvg/resvg-js` | Рендер SVG→PNG только для служебных `npm run snapshot`/осмотра, не в продукте |
| `lucide-vue-next` | Единый набор иконок UI |
| `@fontsource-variable/inter` | Локальный шрифт Inter без внешнего CDN (основной текст/мелкий UI) |
| `@fontsource-variable/fredoka` | Локальный дисплейный шрифт для заголовков и акцентных элементов — более дружелюбный/округлый, поддерживает пастельную «девчачью» тему (раздел 7 ТЗ) |
| `canvas-confetti` | Лёгкий (~2 КБ) эффект конфетти при успешной сборке композиции в обоих сценариях; чисто декоративная UI-реакция, не затрагивает core/*; уважает `prefers-reduced-motion` |
