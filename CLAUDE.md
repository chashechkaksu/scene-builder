## 1. Задача (сохранить как docs/SPEC.md)

Разработать веб-сервис, который из отдельных компонентов (иллюстративных объектов) собирает композиции для иллюстраций в разных форматах. Процесс автоматизирован.

**Сценарий 1.** Человек вводит метафору или заголовок, программа сама подбирает подходящие объекты и собирает композицию.
**Сценарий 2.** Человек вводит названия нужных компонентов, программа компонует их в композицию.

**Ключевое ограничение.** Сервис не генерирует новые объекты. Итоговая композиция состоит только из элементов исходных 20 иллюстраций. Объекты никак не меняются. Результат векторный (SVG). AI-инструменты разрешены для разработки и для анализа метафор.

**Что должен уметь сервис**

1. Работа с SVG и библиотекой: использовать заранее подготовленную библиотеку SVG, сохранять векторную структуру, цвета и пропорции.
2. Сборка композиции: добавлять элементы на холст, перемещать, поворачивать, дублировать, удалять, управлять порядком слоёв, собирать сцену из элементов нескольких иллюстраций, давать выбор размера и цветовой схемы.
3. Палитра: загрузка цветовой палитры в сервис и автоматическая перекраска композиции (как это делает плагин в Figma).
4. Экспорт: скачивание композиции в SVG, векторность и редактируемость объектов сохраняются, никакой растеризации.

**Предметные правила**

- Иллюстрации бывают 2 размеров (**L** и **S**), разница в детализации. Выбор размера автоматически подгружает соответствующие элементы.
- Сейчас 3 цветовые схемы, в будущем их может стать больше (добавление схемы не должно требовать правок кода).
- Объекты бывают **главные** (цветные) и **фоновые** (монохром). В зависимости от смысла и композиции фоновые можно использовать или не использовать.
- Цвета фонов могут использоваться в объектах. Цвета объектов не могут использоваться в фонах.
- Композиция: **можно** менять расположение объектов, их состояние (главный/фоновый) и цвета. **Нельзя** менять пропорции объектов относительно друг друга, сам объект и его элементы (объект только копируется), нарушать цветовую схему.
- Форматы композиций: квадрат, горизонталь, вертикаль.

**Что оценивается:** качество решений и работающий результат, а не количество функций.

**Что сдаём:** ссылку на работающий сервис, исходный код, краткое описание архитектуры (хранение, извлечение и переиспользование SVG-элементов), список использованных AI-инструментов, 2–3 примера собранных композиций.

## 3. Принятые решения (не пересматривать без причины)

| Вопрос | Решение |
|---|---|
| Формат сервиса | Веб-приложение, SPA без бэкенда |
| Стек | Vue 3 (Composition API, `<script setup lang="ts">`) + TypeScript (strict) + Vite + Pinia |
| Подбор объектов (сценарий 1) | Локальный семантический движок на заранее подготовленном словаре смыслов. **Без внешних API и без ключей.** (В одной из рабочих версий был опциональный ИИ-режим через ключ Anthropic — по решению пользователя удалён, сервис полностью локальный) |
| Комментарии в коде | Не писать. Код должен читаться сам: понятные имена, небольшие функции, чистые типы. Допустимы только JSDoc у публичного API модулей `core/` и редкие комментарии про неочевидные инварианты SVG |
| Масштаб объектов | Пользователь **не** масштабирует объекты по отдельности (правило о пропорциях). Все объекты сцены масштабируются **одним общим коэффициентом сцены** `Scene.objectScale` (по умолчанию авто, диапазон 0,3–1,0; авто считает `core/layout` по самому крупному объекту так, чтобы его bbox занимал не более ~62% площади кадра). Коэффициент применяется только к внешней группе экземпляра (как поворот): относительные размеры объектов, их геометрия и элементы не меняются. Выбор L/S подгружает другой набор файлов, а не множитель |
| Тема оформления | Светлая, нежная, пастельная (см. раздел 7) |

## 4. Архитектура

Принцип: **SVG-библиотека обрабатывается один раз на этапе сборки, рантайм только читает готовый манифест и рисует `<symbol>` через `<use>`**. Объекты нигде не переписываются, меняется только цвет через роли и трансформ обёртки.

```
assets-src/            исходные SVG из Figma (только читаются)
scripts/
  build-library.ts     валидация, классификация цветов по ролям, генерация src/library/*
src/
  library/             СГЕНЕРИРОВАНО: manifest.json + нормализованные svg (не править руками)
  core/                чистая логика без Vue и DOM: palette, recolor, layout, matcher, export, geometry
  features/
    canvas/            SVG-холст, выделение, drag, rotate, hotkeys
    library-panel/     список объектов, поиск, размер L/S
    scenarios/         ввод метафоры, ввод компонентов
    palette/           выбор схемы, загрузка JSON, редактор 8 цветов
    layers/            список слоёв, порядок
    export/            кнопка и диалог экспорта
  stores/              Pinia: scene, library, palette, ui
  shared/              strings, типы, утилиты
tests/
  unit/                Vitest
  e2e/                 Playwright
docs/                  SPEC.md, ARCHITECTURE.md, AI_TOOLS.md, examples/
```

### 4.1 Хранение SVG

- Исходники лежат в `assets-src/` и считаются неприкосновенными оригиналами.
- `scripts/build-library.ts` (запускается `npm run library`) делает следующее:
  1. Парсит каждый SVG (XML-парсер, не регулярки).
  2. **Валидирует:** нет `<image>`, нет встроенного растра, нет внешних ссылок, есть `viewBox`. При нарушении падает с понятной ошибкой и именем файла.
  3. Не изменяет геометрию. Запрещено прогонять через оптимизаторы, которые переписывают `d`, трансформы или порядок элементов. Допустимо только удалить комментарии, метаданные и пустые `defs`, и только если это ни на что не влияет.
  4. **Классифицирует цвета.** Каждый fill/stroke сопоставляется с **ролью** по каноническому набору (фиолетовая схема, раздел 5). Нужные атрибуты заменяются на `data-role="bg-2"` и т. п. вместе с запасным `fill` в исходном hex. Цвета, которых нет в каноне, выводятся в отчёт, **сборка падает**, пока пользователь не решит, что с ними делать. Тихо подбирать ближайший цвет нельзя.
  5. Префиксует все `id`, `clipPath`, `mask`, `url(#...)` уникальным префиксом `{id}-{size}-{state}-`, чтобы объекты не конфликтовали в одном документе.
  6. Считает `bbox` и точку привязки каждого объекта, пишет `src/library/manifest.json`.
- Манифест (тип `LibraryManifest`):

```ts
interface LibraryObject {
  id: string
  nameRu: string
  sizes: Record<'L' | 'S', Record<'main' | 'bg', AssetRef>>
  meta: SemanticMeta
}
interface AssetRef {
  file: string
  viewBox: [number, number, number, number]
  bbox: { x: number; y: number; width: number; height: number }
  roles: Role[]
}
```

### 4.2 Извлечение и переиспользование

- Рантайм вставляет все нужные ассеты в один скрытый `<svg>` как `<symbol id="...">`. Экземпляры на холсте это `<use href="#...">` внутри `<g transform>`.
- Один объект на холсте может быть добавлен сколько угодно раз без копирования разметки (дублирование = новый экземпляр с тем же `assetId`).
- Смена размера L/S: `assetId` экземпляра меняется на соответствующий из другого набора, трансформ сохраняется.
- Смена состояния main/bg: то же самое, меняется `state`.
- Ленивая загрузка: при выбранном размере грузятся только ассеты этого размера.

### 4.3 Цвет и перекраска

- В превью цвета берутся из CSS-переменных `--role-bg-1`, `--role-ink` и т. п. на корне холста. Элементы символов используют `fill="var(--role-…, #fallback)"`. Смена палитры это перезапись 8 переменных, **DOM не перерисовывается**.
- Ограничение: правило «цвета объектов не могут использоваться в фонах» обеспечивается структурой. У фоновых ассетов и подложки в манифесте только роли `bg-*` и `ink`. Тест это проверяет.

### 4.4 Модель сцены

```ts
interface SceneItem {
  uid: string
  objectId: string
  state: 'main' | 'bg'
  x: number
  y: number
  rotation: number
  flipX: boolean
}
interface Scene {
  format: 'square' | 'landscape' | 'portrait'
  size: 'L' | 'S'
  paletteId: string
  items: SceneItem[]
}
```

Порядок в массиве `items` равен z-order. Сцена сериализуется целиком (autosave в `localStorage` в `try/catch`, undo/redo поверх неё).

### 4.5 Экспорт

`core/export` превращает сцену в самостоятельный SVG:

- корневой `<svg>` с `viewBox` формата, подложка-фон, затем группы объектов по z-order;
- каждый объект это **инлайн-группа** `<g id="obj-lamp-3" data-object="lamp" data-state="main" transform="…">` с оригинальными элементами внутри (не `<use>`, чтобы объекты было удобно править в Figma/Illustrator);
- все роли **разрешаются в конкретный hex** выбранной палитры (CSS-переменные в файл не попадают, Figma их не понимает);
- id внутри экземпляров переприсваиваются уникально;
- никакого `<image>`, никаких data-URI, никаких растровых фильтров;
- скачивание через `Blob` и `<a download>`.

**Инвариант:** для каждого экспортированного объекта набор геометрических атрибутов (`d`, `points`, `cx/cy/r`, `x/y/width/height` и т. д.) идентичен исходному. Меняются только цвета и внешний `transform`. Это golden-тест (раздел 11).

## 5. Цветовая модель

Палитра это 8 ролей, как в блоках «Цвета фона / Цвета объектов» из Figma. Порядок сверху вниз:

| Роль | Колонка | Смысл |
|---|---|---|
| `bg-1` | Цвета фона | самый светлый оттенок (подложка) |
| `bg-2` | Цвета фона | средний |
| `bg-3` | Цвета фона | тёмный |
| `ink` | Цвета фона | чёрный (контуры, тени) |
| `obj-1` | Цвета объектов | акцент 1 (в фиолетовой схеме жёлтый) |
| `obj-2` | Цвета объектов | акцент 2 (розовый) |
| `obj-3` | Цвета объектов | акцент 3 (светло-розовый) |
| `white` | Цвета объектов | белый |

Формат палитры (JSON, валидируется схемой `zod`):

```json
{
  "id": "purple",
  "name": "Фиолетовая",
  "background": { "bg1": "#D7CDF5", "bg2": "#...", "bg3": "#...", "ink": "#1A1A1A" },
  "object": { "obj1": "#...", "obj2": "#...", "obj3": "#...", "white": "#FFFFFF" }
}
```

- Точные hex-значения берутся из `assets-src/palettes/*.svg` (скрипт извлекает заливки блоков по порядку). Известно только, что фиолетовая `bg-1` = `#D7CDF5`. Остальное брать **из файлов**, не угадывать.
- Канонической схемой для классификации цветов ассетов считается **фиолетовая** (в ней нарисованы цветные объекты и фоновые монохромные).
- Три встроенные палитры лежат в `src/palettes/*.json`. Новая палитра это новый JSON, без правки кода. Реестр палитр собирается через `import.meta.glob`.
- Загрузка: кнопка «Загрузить палитру (.json)», drag-and-drop, валидация с понятными ошибками, плюс встроенный редактор (8 цветовых полей) с кнопкой «Скачать JSON».
- Контраст-проверку не навязывать, но показывать мягкое предупреждение, если `bg-1`, `bg-2`, `bg-3` практически неотличимы.

## 6. Функциональные требования

### 6.1 Холст и редактор

- Добавление объекта из библиотеки: клик и перетаскивание на холст.
- Выделение (клик, Shift для нескольких, рамка), перемещение, **поворот** (ручка над объектом, шаг 15° при Shift), **дублирование** (Ctrl/Cmd+D, Alt+drag), **удаление** (Delete/Backspace).
- Порядок слоёв: на передний план, вперёд, назад, на задний план (кнопки и хоткеи `]`, `[`, `Ctrl+]`, `Ctrl+[`), панель слоёв с drag-сортировкой.
- Переключатель состояния выделенного объекта: главный ↔ фоновый.
- Отзеркаливание по горизонтали допустимо как «состояние расположения», но только если не ломает изометрическую логику света. Если сомневаешься, не добавляй.
- Undo/redo (Ctrl+Z / Ctrl+Shift+Z), зум и панорамирование холста (колесо, пробел+drag), привязка к рамке формата.
- Объекты могут выходить за границы формата (в примерах они обрезаются краем). Экспорт обрезает по `viewBox` через `clipPath` корня.
- Размеры на экране адаптивные, но холст сохраняет пропорцию формата.

### 6.2 Сценарии

**Сценарий 1: метафора или заголовок.**

- Поле ввода + кнопка «Собрать». Пример: «Защита личных данных», «Идея, которая зажигает», «Финансовая грамотность».
- `core/matcher` возвращает список `{ objectId, score, reasons[] }`. Выбирает 2–5 объектов, причём первые 1–3 главные, остальные фоновые. Причины показываются пользователю («Лампа: идея, инсайт»), это часть качества, не пропускай.
- Если совпадений слишком мало, выбирается нейтральный набор по доминирующей теме и показывается сообщение «Точных совпадений нет, подобрали близкие по смыслу».
- Кнопка «Другой вариант» перегенерирует **раскладку** (другой seed), набор объектов остаётся, плюс «Заменить объект» для альтернатив из рейтинга.

**Сценарий 2: названия компонентов.**

- Поле с чипами и автодополнением (название на русском, id, синонимы). Принимает «книга, телефон, наушники», «лампа и ручка» и т. п. Нечёткое совпадение по опечаткам (расстояние Левенштейна ≤ 1–2 в зависимости от длины).
- На каждом чипе переключатель «главный/фоновый». Неизвестные слова подсвечиваются и не блокируют остальное.
- Дальше те же правила раскладки.

### 6.3 Форматы

Подтверждённые пользователем размеры (раздел 2.2), все в единицах viewBox:

| Формат | Размер |
|---|---|
| Квадрат | 1000 × 1000 |
| Горизонталь | 1200 × 630 |
| Вертикаль | 800 × 1200 |

Реестр форматов лежит в одном файле конфигурации (`src/shared/formats.ts`). Добавление формата не требует правок логики.

Поверх пресетов пользователь может задать **свой размер холста** (панель «Холст»: слайдеры ширины/высоты, либо ручки прямо на холсте) — ограничен диапазоном 400–2400 по каждой стороне. Свой размер временно переопределяет пресет (`Scene.customSize`), выбор одного из трёх пресетов форматов сбрасывает его обратно. Общий масштаб объектов сцены (раздел 3) от размера кадра не зависит напрямую: в авто-режиме он пересчитывается по самому крупному объекту и площади кадра, вручную регулируется ползунком «Масштаб объектов» (кнопка «Авто» возвращает автоматический).

### 6.4 Подложка

Подложка берётся из `assets-src/backgrounds` выбранной схемы и размера: заливка `bg-1`, декоративные линии и овалы в `bg-2/bg-3`. Для неквадратных форматов подложка масштабируется **по принципу `slice`** (заполняет формат, лишнее обрезается). Новые декоративные элементы не рисуются. Подложка отдельный слой, всегда самый нижний, и её можно выключить (останется сплошной `bg-1`).

### 6.5 Автораскладка (`core/layout`)

Цель: композиция выглядит как примеры со страницы «Примеры композиций» (изометрические объекты, пересечения, часть объектов обрезана краем, фоновые крупно и приглушённо позади, главные впереди).

Алгоритм (детерминированный, `seed` → результат):

1. Единый коэффициент плотности раскладки: подбирается из формата и числа объектов (чем больше объектов в сцене, тем теснее расставлены якоря раскладки, и наоборот) — это общий для всей сцены параметр самой раскладки, а не масштаб объектов. Размер самих объектов задаётся одним общим коэффициентом сцены `Scene.objectScale` (раздел 3): раскладка считает bbox с учётом этого коэффициента, относительные размеры объектов не меняются. Дополнительно в скоринге есть штрафы читаемости: видимая часть главного объекта (с учётом обрезки и перекрытий) ≥ 65%, перекрытие главного другим главным ≤ 35%, площадь bbox объекта не больше порога, производного от авто-масштаба. Выбор L/S подгружает готовый набор файлов другой детализации, а не множитель.
2. Генерируется N кандидатов (например 200) через seeded PRNG (`mulberry32`): позиции вокруг якорных точек формата (правило третей), небольшие повороты в допустимом диапазоне, z-order: сначала фоновые, затем главные.
3. Каждый кандидат оценивается функцией: покрытие кадра, баланс центра масс, разумная доля пересечений по bbox, минимум полностью вылетающих за край объектов, главный объект заметен, нет «склейки» двух объектов в точку.
4. Побеждает лучший кандидат. «Другой вариант» увеличивает seed.
5. Все пороги и веса вынести в именованные константы одного модуля, они покрыты тестами на свойства (раздел 11).

### 6.6 Семантический словарь (`src/library/semantics.ts`, ручная часть)

Для каждого из 10 объектов Claude Code **при разработке** составляет словарь смыслов: 40–80 слов и фраз на русском и английском (прямые значения, метафоры, ассоциативные области, синонимы), разбитый на уровни веса: `literal` (1.0), `strong` (0.7), `associative` (0.4). Примеры направлений: лампа это идея, озарение, поиск решения, ночная работа, уют, чтение; пазл это решение, интеграция, часть целого, сложная задача, совместимость; монета это деньги, экономия, стоимость, инвестиции; кошелёк это бюджет, оплата, покупки; наушники это музыка, подкаст, концентрация, звук, обучение; книга это знание, учёба, история, дневник, чтение; телефон это связь, приложение, мобильный, уведомление; папка это документы, организация, проект, архив; ручка это письмо, подпись, заметки, договор; тюльпаны это весна, подарок, забота, праздник, рост.

Движок:

- нормализация (нижний регистр, `ё→е`, пунктуация), токенизация, русская стемминг-обработка (подключить компактный пакет или написать небольшой стеммер; выбрать лёгкий вариант), стоп-слова;
- TF-IDF-подобное взвешивание по уровням и редкости слова, n-граммы для устойчивых фраз («личные данные»);
- нечёткое сравнение для опечаток;
- нормализованный score 0–1 и список причин.
- Список из ~30 тестовых метафор с ожидаемыми объектами хранится в `tests/fixtures/metaphors.json` и используется как регрессионный набор (минимальная доля попаданий задать и зафиксировать, например ≥ 85 %).

## 7. Дизайн интерфейса

- Нежный, воздушный, пастельный, в духе иллюстраций задания. Основа: лавандовый `#D7CDF5` (точный) и два соседних акцентных семейства (персиковое и мятно-бирюзовое), их точные hex взять из палитр в `assets-src/palettes`. Никаких кислотных цветов и жёстких чёрных рамок.
- Токены в CSS-переменных (`src/styles/tokens.css`): цвета, радиусы (крупные, 12–20 px), мягкие тени, отступы по сетке 4/8 px, типографика.
- Шрифт: Inter (пакет `@fontsource-variable/inter`), чёрный текст `#1A1A1A` на светлом.
- Макет: верхняя панель (выбор сценария, поле ввода, размер L/S, формат, палитра, экспорт), слева библиотека, по центру холст, справа свойства и слои. На узких экранах панели становятся выдвижными.
- Состояния: пустой холст с подсказкой, загрузка, ошибки валидации палитры, пустой результат подбора. Кнопки с видимым фокусом, управление с клавиатуры, `aria-label` на иконках.
- Анимация лёгкая (появление объектов при сборке композиции, плавная смена палитры через `transition` на CSS-переменных). Уважать `prefers-reduced-motion`.
- Иконки: единый набор (например `lucide-vue-next`), без эмодзи.

Используй навык `frontend-design`, если он доступен, и проверяй результат скриншотами (раздел 11.4).

## 8. Качество кода

Менеджер пакетов: **npm** (`package-lock.json`, без pnpm и yarn). Скрипты в `package.json` вызывают друг друга через `npm run`.

- `strict: true`, без `any` (исключения оформлять явным типом), `noUncheckedIndexedAccess`.
- Логика в `core/` чистая и покрыта тестами, Vue-компоненты тонкие. Работа с состоянием через Pinia, побочные эффекты (DOM, localStorage, скачивание) только на границах.
- Производительность: холст с 50+ объектами работает без подтормаживаний. `<use>` + CSS-переменные, `shallowRef` для больших структур, `v-memo`/`computed` по месту, drag обновляет только `transform` выбранной группы.
- ESLint (`@antfu/eslint-config` или `typescript-eslint` + `eslint-plugin-vue`) и Prettier. Скрипты:

```
npm run dev | build | preview   # (npm run dev, npm run build, npm run preview)
npm run library        # сборка манифеста из assets-src
npm run typecheck      # vue-tsc --noEmit
npm run lint | format      # (npm run lint, npm run format)
npm run test           # vitest run
npm run e2e            # playwright test
npm run snapshot       # рендер примеров в PNG для визуальной проверки
npm run examples       # генерация docs/examples/*.svg
npm run verify         # library && typecheck && lint && test && build && e2e
```

- **Git не используется.** Не запускать `git init`, не делать коммиты и ветки, не опираться на git-команды в скриптах, хуках и агентах. Файл `.gitignore` создать можно (`node_modules`, `dist`), это просто файл на будущее. Проект живёт как обычная папка, пользователь сам зальёт его в репозиторий позже.
- Зависимости минимум и по делу. Каждую новую зависимость оправдать в `docs/ARCHITECTURE.md` одной строкой.

## 9. Окружение агентов (настроить первым делом)

Основная сессия это **тимлид-оркестратор**: планирует, делегирует, принимает работу, ничего не принимает «на слово». Специалисты работают в изолированном контексте и возвращают краткий отчёт.

### 9.1 Субагенты

Создай файлы `.claude/agents/<name>.md` с frontmatter (`name`, `description`, `tools`, при желании `model`). Актуальный формат сверь с документацией Claude Code. Роли:

| Агент | Задача | Инструменты |
|---|---|---|
| `svg-pipeline` | `scripts/build-library.ts`, валидация, роли, манифест, `core/export` | чтение, правка, Bash |
| `editor-engineer` | холст, выделение, drag/rotate, слои, undo/redo, горячие клавиши | чтение, правка, Bash |
| `semantic-matcher` | словарь смыслов, `core/matcher`, регрессионный набор метафор | чтение, правка, Bash |
| `layout-engineer` | `core/layout`, скоринг, форматы, подложка | чтение, правка, Bash |
| `ui-designer` | токены, компоненты, адаптив, состояния, a11y, визуальная полировка | чтение, правка, Bash, просмотр изображений |
| `qa-tester` | Vitest, Playwright, property-тесты, скриншоты; пишет тесты и **не правит продуктовый код** | чтение, правка только в `tests/`, Bash |
| `code-reviewer` | **только чтение.** Ищет баги, нарушения архитектуры, лишнюю сложность, утечки, производительность | чтение, Grep, Bash (без записи) |
| `spec-auditor` | **только чтение.** Сверяет реализацию с `docs/SPEC.md` построчно, ищет расхождения | чтение, Grep, Bash (без записи) |

Пример файла:

```markdown
---
name: code-reviewer
description: Независимый ревьюер изменённых файлов. Используй после каждого этапа перед приёмкой. Только чтение.
tools: Read, Grep, Glob, Bash
---
Ты строгий ревьюер. Не пиши и не правь код. Оркестратор передаёт тебе цель этапа и список изменённых и добавленных файлов. Прочитай эти файлы целиком.
Проверь: корректность, граничные случаи, типы, соответствие архитектуре из CLAUDE.md, неизменность SVG-объектов, производительность, читаемость.
Выведи список находок: серьёзность (blocker/major/minor), файл:строка, суть, как воспроизвести, предложение исправления. Если проблем нет, скажи это явно и перечисли, что именно проверил.
```

### 9.2 Слэш-команды (`.claude/commands/`)

- `/verify`: запуск `npm run verify`, краткая сводка, при падении анализ причин.
- `/review`: запуск `code-reviewer` и `spec-auditor` на файлах, изменённых на текущем этапе, сведение их отчётов, список правок.
- `/snapshot`: рендер примеров в PNG и визуальный осмотр (см. 11.4).
- `/stage-done`: проверка гейтов этапа (раздел 10), при полном прохождении фиксирует этап как принятый в `docs/PROGRESS.md`.

### 9.3 Хуки (`.claude/settings.json`)

- `PostToolUse` по `Edit|Write`: форматирование изменённых файлов (Prettier) и быстрый `eslint --fix` на них.
- `Stop`: быстрый `npm run typecheck`, чтобы сессия не заканчивалась с ломаным типизированием. Если проверка падает, исправить до остановки.
- `PreToolUse` на `Edit|Write`: **запретить правку `assets-src/` и `src/library/`** (первое неприкосновенно, второе генерируется). Вернуть понятное сообщение.
- Не делать хуки тяжёлыми. Тесты и сборку запускать вручную и командами выше.

### 9.4 Цикл контроля качества (обязателен для каждого этапа)

```
план этапа (оркестратор, TaskCreate)
  → реализация (профильный агент)
  → qa-tester: тесты + запуск
  → code-reviewer: независимый ревью изменённых файлов
  → spec-auditor: сверка с docs/SPEC.md
  → исправления по blocker/major (максимум 3 круга; если не сходится, остановиться и описать проблему пользователю)
  → /verify зелёный
  → этап принят: запись в `docs/PROGRESS.md` (что сделано, что проверено)
```

Правила для агентов: ревьюер и аудитор **не видели** процесса реализации, им передают цель этапа и список файлов, а не рассуждения. Отчёты короткие и фактические. Любое «готово» подтверждается запуском команд. Если инструмент или файл отсутствует, агент говорит об этом, а не выдумывает.

## 10. Этапы и гейты

**Этап 0. Каркас.** Vite + Vue 3 + TS strict + Pinia + ESLint/Prettier + Vitest + Playwright, структура папок, агенты, команды, хуки, `docs/SPEC.md`.
*Гейт:* `npm run verify` проходит на пустом приложении, хуки срабатывают.

**Этап 1. Библиотека и палитры.** `build-library.ts`, роли, манифест, `core/palette`, схема палитры, три встроенные палитры из `assets-src/palettes`.
*Гейт:* все 40 ассетов + подложки собраны; отчёт о неклассифицированных цветах пуст (или согласован с пользователем); тесты ролей и фонов проходят.

**Этап 2. Холст и редактор.** Символы, добавление, drag, rotate, дублирование, удаление, слои, undo/redo, зум.
*Гейт:* e2e «добавить, повернуть, продублировать, удалить, поменять порядок» проходит; 50 объектов без лагов.

**Этап 3. Цвет, размер, формат.** Переключатель L/S, форматы, подложка, смена палитры и загрузка JSON, редактор палитры.
*Гейт:* смена размера сохраняет позиции; перекраска не перерисовывает DOM; невалидный JSON даёт понятную ошибку.

**Этап 4. Экспорт.** `core/export`, скачивание SVG.
*Гейт:* golden-тест неизменности геометрии, отсутствие растра, корректное открытие результата (рендер через `@resvg/resvg-js` совпадает с превью по визуальной проверке).

**Этап 5. Автоматизация.** Автораскладка, сценарий 1 (словарь и движок), сценарий 2 (чипы и нечёткий поиск).
*Гейт:* регрессионный набор метафор ≥ порога; раскладка детерминирована по seed; e2e обоих сценариев.

**Этап 6. Дизайн и полировка.** Токены, адаптив, состояния, a11y, анимация. Осмотр скриншотов.

**Этап 7. Сдача.** README (запуск, примеры), `docs/ARCHITECTURE.md` (краткое описание хранения, извлечения и переиспользования SVG), `docs/AI_TOOLS.md` (какие AI-инструменты и для чего использовались: Claude Code для разработки и для составления семантического словаря; честно и без приукрашивания), `docs/examples/` с 3 SVG-композициями (генерируются `npm run examples` из сидов), деплой, проверка живой ссылки.
*Гейт:* `npm run verify` зелёный после чистой установки (`rm -rf node_modules dist && npm install && npm run verify`); живая ссылка открывается; экспорт из деплоя открывается в Figma или браузере корректно.

## 11. Тестирование и проверки

### 11.1 Unit (Vitest)

- `palette`: валидация схемы, разбор hex, ошибки.
- `build-library`: отклоняет `<image>`, внешние ссылки, неизвестные цвета; префиксация id; манифест соответствует файлам.
- Роли: у каждого `bg`-ассета только роли `bg-*`/`ink`; у `main`-ассетов допустим любой набор ролей; подложка только `bg-*`/`ink`.
- `recolor`: смена палитры подставляет верные hex на все роли; роль без значения в палитре даёт ошибку, а не чёрный цвет.
- `export`: **golden-тест геометрии** (все геометрические атрибуты совпадают с исходником), нет `<image>`/`data:`/`var(`, id уникальны, корневой viewBox равен формату, число групп равно числу объектов.
- `matcher`: регрессионный набор метафор, пустой ввод, мусор, очень длинный ввод, опечатки.
- `layout`: property-тесты (при любом seed все объекты хотя бы частично в кадре, число и состав объектов сохраняются, масштаб единый, главные объекты видны не менее порога, результат детерминирован).

### 11.2 E2E (Playwright)

Сценарий 1, сценарий 2, ручное редактирование, смена размера/палитры/формата, загрузка палитры, экспорт (скачанный файл парсится, не пуст, без растра), undo/redo.

### 11.3 Ручной чек-лист перед сдачей

Пройти все пункты раздела 1 и отметить каждый в `docs/CHECKLIST.md` (генерирует `spec-auditor`).

### 11.4 Визуальная проверка

`npm run snapshot` рендерит набор сцен (3 формата × 3 палитры × 2 размера) в PNG через `@resvg/resvg-js`. Агент `ui-designer` или оркестратор **смотрит эти изображения** и сравнивает с `assets-src/reference/` (стиль, пропорции, нет ли «вылезших» объектов, не перепутаны ли цвета). Замечания идут в цикл исправлений.

## 12. Чего не делать

- Не генерировать, не перерисовывать, не «чистить» и не упрощать объекты. Не использовать оптимизаторы SVG, переписывающие геометрию.
- Не растеризовать ничего ни в превью-логике экспорта, ни в итоговом файле. (PNG допустимы только в `snapshot` для проверки, не в продукте.)
- Не масштабировать объекты по отдельности, не менять пропорции.
- Не использовать цвета объектов в подложке и фоновых объектах.
- Не добавлять внешние API, ключи, бэкенд, лишние функции «на будущее».
- Не править `assets-src/` и `src/library/` вручную (кроме ручного файла-исключения `src/library/semantics.ts`, раздел 6.6).
- Не оставлять комментарии-пояснения в коде и закомментированный код.
- Не объявлять этап завершённым без запуска гейтов.
